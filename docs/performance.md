# 성능·호출 예산 기준

M4에서 외부 제공자 호출량과 시간 제한을 코드 설정값으로 고정하고, 실제 제공자 키가 없어도 회귀 검증할 수 있도록 했다. 2026-08-20에는 NAVER API HUB 지역 검색 권한을 추가한 뒤 장소 후보 API의 실호출도 확인했다.

## 요청당 최악 호출량

기본 설정(`maxEventsPerAnalysis=100`, 목적지 반경 15km)에서 논리적 외부 호출은 다음 상한을 따른다.

| 단계                  |            상한 |
| --------------------- | --------------: |
| 주소 지오코딩         |             2회 |
| 자동차 경로           |             1회 |
| 목적지 주변 행사 검색 |             1회 |
| 행사 기간 검색        |             0회 |
| 행사 상세 공통·소개   | 0회 (후속 단계) |
| 방문객 참고값·집중률  |        최대 2회 |
| 날씨                  |             1회 |
| 합계                  |        최대 7회 |

좌표 입력이면 지오코딩 호출은 줄어든다. 현재 MVP는 목적지 반경 후보의 날짜·키워드·중복 조건을 확인해 행사 개수와 밀집 가능성만 계산하며, 행사 상세 조회는 후속 단계로 미룬다. 외부 HTTP 클라이언트는 재시도 가능한 타임아웃·429·5xx에 대해 요청당 최대 2회 시도하므로, 장애 시 물리적 시도량의 최악 상한은 논리적 호출량의 2배다.

장소 후보 조회는 분석 요청과 별도 엔드포인트다. 모바일 입력창이 300ms debounce와 이전 요청 취소를 적용하므로 빠른 타이핑 중 불필요한 응답 반영을 줄인다. `limit`은 최대 5이며, 숫자가 포함된 완성형 도로명 주소에는 후보 요청을 보내지 않는다. 후보 API 호출은 분석 요청의 외부 호출 예산에 포함하지 않지만 NAVER API HUB의 제공자 한도 안에서 관리해야 한다.

모든 외부 HTTP 요청은 인스턴스 내 동시성 세마포어(`maxConcurrentUpstreamRequests=10`)를 공유한다. Cloud Run 기본 목표는 인스턴스 동시 요청 10개 이하이며, 실제 배포 시 서비스 설정과 함께 확인한다.

## 시간 기준

- FastAPI 분석 전체 제한: 60초
- 모바일 API 클라이언트 제한: 55초
- 목표: 정상적인 단거리 요청의 p50 10초 이하, p95 30초 이하
- 허용 실패: 제공자 지연으로 60초를 넘으면 `504 ANALYSIS_TIMEOUT`, 일부 제공자만 실패하면 가능한 데이터와 경고를 함께 반환

p50·p95와 동시 요청 메모리 측정은 실제 Cloud Run 후보 Revision에서 별도로 수행해야 한다. 현재 저장소에는 제공자 MockTransport 기반 호출 상한·타임아웃 회귀 테스트가 있다.
