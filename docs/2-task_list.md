## 2. 상태와 우선순위

- `[ ]`: 시작 전

- `T-102`: iOS Simulator 릴리스 흐름 통과, Cloud Run 후보 Revision·Android·실기기 회귀 필요

한국관광공사·방문객·기상청 엔드포인트와 NAVER Maps·NAVER API HUB Local Search는 실제 인증정보로 최소 요청 `HTTP 200`을 확인했다. Local Search는 `서울역`·`부산역` 후보와 주소·좌표를 반환했고, iOS Simulator에서 후보 선택 후 분석까지 재실행했다. 목적지 행사 목록은 1회, 행사 상세 조회는 0회인 count-only 흐름을 유지한다. M4 호출 예산·타임아웃·보안 경계 자동 검증도 통과했지만, 컨테이너 실행·Cloud Run 성능·Android·실기기·법무 검증은 남아 있다.

장소명이 여러 후보를 반환하는 경우에는 잘못된 위치를 임의 선택하지 않도록 모바일에서 후보 선택을 요구한다. 선택 없이 `서울역` 같은 모호한 값을 직접 분석 API에 제출하는 동작은 `LOCATION_NOT_FOUND`가 될 수 있으며, 이는 주소 오인 분석을 막기 위한 현재 정책이다.

모바일은 `npm test -- --runInBand`, TypeScript, ESLint, Prettier 및 `npx expo export --platform web` 검증을 통과했다. 실제 NAVER 네이티브 지도, 지역 추천, 주소 선택 및 count-only 분석 흐름은 iOS Simulator Development Build에서 확인했으며, Android·iOS 실기기 흐름은 남아 있다.

## 6. 공통 완료 원칙

- 사용자 입력과 분석 결과를 서버 또는 앱의 영구 저장소에 저장하지 않는다.
- API 키를 앱 번들, Git 저장소, Docker 이미지, API 응답 및 로그에 포함하지 않는다.
- 외부 API 일부 실패 시 전체 요청을 무조건 실패시키지 않고 가능한 결과와 경고를 반환한다.
- 문서 상태는 구현 및 검증 결과와 함께 갱신한다.
